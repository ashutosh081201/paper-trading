# Deploying StockLab

The API runs on **Render**, the frontend on **Vercel** and the database on **MongoDB Atlas**, all on free tiers. Deploy in this order: database, then API, then frontend, then point the API's CORS setting at the frontend URL.

## 1. MongoDB Atlas

1. Create a free **M0** cluster.
2. **Database Access:** add a database user with a strong password.
3. **Network Access:** add `0.0.0.0/0`. Render's free tier has no fixed outbound IP, so the cluster has to accept connections from anywhere; the database user's password is what protects it.
4. **Connect → Drivers:** copy the `mongodb+srv://…` connection string and add a database name before the `?`, for example `…mongodb.net/stocklab?retryWrites=true&w=majority`.

Atlas pauses free clusters after a long period without use, and a paused cluster's hostname stops resolving (the API then logs `querySrv ENOTFOUND`). Resume it from the Atlas dashboard if that happens.

## 2. Email (Brevo)

Render's free tier blocks outbound SMTP, so Gmail SMTP won't work there. The API sends mail through Brevo's HTTPS API whenever `BREVO_API_KEY` is set.

1. Create a free Brevo account.
2. **Senders, domains & dedicated IPs → Senders:** add and verify the address mail should come from.
3. **SMTP & API → API keys:** create a key.

Locally you can keep using Gmail SMTP (`EMAIL_USER` and an app password in `EMAIL_PASS`) and leave `BREVO_API_KEY` empty.

## 3. API on Render

1. **New → Blueprint**, connect the GitHub repository. Render reads `render.yaml` from the repo root.
2. Fill in the values Render asks for:

   | Variable | Value |
   | --- | --- |
   | `MONGO_URL` | Atlas connection string |
   | `BREVO_API_KEY` | Brevo API key |
   | `EMAIL_FROM` | the verified Brevo sender |
   | `UPSTOX_ANALYTICS_TOKEN` | optional; without it prices come from Yahoo Finance |
   | `GEMINI_API_KEY` | optional; AI sentiment |
   | `NEWS_API_KEY` | optional; market news |
   | `CORS_ORIGINS` | leave empty for now |

   `TOKEN_KEY` is generated by Render.
3. Deploy. When it's live, open `https://<your-service>.onrender.com/api/health`. It should return `{"status":"ok","database":true}`.

The free instance sleeps after 15 minutes without traffic; the next request wakes it in about a minute. Cron jobs don't run while it sleeps — intraday positions left open are closed when it wakes up.

## 4. Frontend on Vercel

1. **Add New → Project**, import the repository and set the **Root Directory** to `frontend`. Vercel detects Vite.
2. Add the environment variable `VITE_API_URL` = `https://<your-service>.onrender.com` (no trailing slash).
3. Deploy. `frontend/vercel.json` rewrites every path to `index.html`, so refreshing a page like `/portfolio` works.

## 5. Connect them

Back in Render, set `CORS_ORIGINS` to the Vercel URL, for example `https://stocklab.vercel.app`, and redeploy. Several origins can be listed, separated by commas.

## Checking the deployment

- `GET /api/health` returns 200 with `"database": true`.
- `GET /api/stocks/list` without a token returns 401.
- The site loads, and refreshing `/login` or `/portfolio` doesn't 404.
- In the browser's network tab, API calls go to the Render URL with no CORS errors.
- Sign up with a real email address and receive the OTP.

## Lockfiles

Render currently builds with npm 10. The lockfiles were generated with npm 10 so `npm ci` passes there; regenerate them with `npx npm@10 install` if you add dependencies with a newer npm.
